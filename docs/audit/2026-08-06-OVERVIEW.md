# 工作区 / 多租户审计（ADR-0007 收尾）— 概览

## 完成内容
对 Aegis 所有数据对象的工作区作用域做了三层审计（Store 层 / Handler 层 core+enterprise / 删除护栏），产出审计报告 `docs/audit/2026-08-06-workspace-multitenant-audit.md`。

## 核心结论
- **已合规**：datasource、dataset、table_permission、row_policy（读/写/删均正确绑定工作区；dataset 为 ADR-0007 已修）。
- **发现 6 个缺口**，全因写路径把裸 `r.Context()` 传进 store——在 admin 默认的 `*` 跨工作区视图下 `WriteWorkspace` 解析为 `default`，对象被静默错配到 `default`：
  - GAP-1 列脱敏掩码（`masks.go:238`）
  - GAP-2 权限审批申请（core `approval.go:108` + enterprise `handlers.go:994`）
  - GAP-3 审批通过后授予的表权限（core `approval.go:198` + enterprise `handlers.go:1060`）
  - GAP-4 数据目录文件夹（enterprise `handlers.go:398`，无 `workspace_id`）
  - GAP-5 指标定义（enterprise `handlers.go:893`）
  - GAP-6 `DeleteMetric` 完全无工作区过滤（store `metric.go:124`）
- 删除护栏整体合规（除 GAP-6），非 `*` 视图均按工作区过滤；`*` 视图留给平台 admin。

## 风险
当前线上 4 个工作区已存在（acme-corp/default/globex/复游会），但既有对象都在 `default`，故为**潜伏**风险；一旦在非 `default` 工作区用掩码/审批/指标/文件夹，admin 默认 `*` 视图会静默错配 → 治理失效 + 跨租户泄漏。

## 优先级（待确认后改代码，不擅自改）
- P0（小改动同构修复）：GAP-1/2/3/5 → 把裸 `r.Context()` 换成 `ds.BoundContext`/`resolveDSBound`
- P1（需补请求字段）：GAP-4 文件夹加 `workspace_id`
- P2（防御一致性）：GAP-6 `DeleteMetric` 加 ctx + 工作区过滤
